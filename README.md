# بیلبوردسنج — تحلیل نقاط بیلبورد تهران

**سایت:** https://ehsan-moeininejad.github.io/Billboard-Master/ · **راهنمای راه‌اندازی قدم‌به‌قدم:** [SETUP.md](SETUP.md)

ابزاری برای تیم‌های مارکتینگ که روی نقشه تهران یک نقطه (بزرگراه، پل عابر، خیابان اصلی) را انتخاب می‌کنند و این‌ها را می‌گیرند:

- **تردد روزانه** خودرو و تعداد افراد در معرض دید
- **میانگین سرعت** و **زمان مواجهه** (چند ثانیه تابلو دیده می‌شود) — به تفکیک ساعت
- **ایمپرشن تخمینی** روزانه، ماهانه و کل کمپین (دیده‌شدن مؤثر، نه صرفاً عبور)
- **CPM** با وارد کردن اجاره ماهانه، **نقشه ارزش** (ایمپرشن در برابر CPM) و **بهینه‌ساز بودجه** (بهترین ترکیب سازه‌ها با بودجه ماهانه)
- **هندسه دید**: عرض سواره‌رو (تعداد خط × 3.5 متر + شانه، یا تگ width در OSM)، فاصله خوانایی از روی ابعاد تابلو، طول دید مستقیم تا اولین پیچ جاده، و پنجره دید هر خط جداگانه — با نمودار
- **سازه‌های موجود**: پل‌های عابر و تابلوهای OSM + ورود فهرست سازه‌ها از اکسل/CSV (با مکان‌یابی خودکار آدرس) + ثبت دستی روی نقشه؛ رتبه‌بندی همه سازه‌های محدوده نقشه
- **جایگاه‌یابی**: سنجش همه معابر محدوده هر 120 متر، حذف نقاط نزدیک سازه‌های موجود، و پیشنهاد بهترین جایگاه‌های خالی با نقشه حرارتی مسیرها
- **برنامه‌ریز کمپین**: بودجه + مدت + هدف (بیشترین ایمپرشن / بیشترین زمان مواجهه / پوشش گسترده) → فهرست پیشنهادی سازه‌ها با هزینه، ایمپرشن، نفر-ساعت مواجهه و CPM؛ قفل/حذف دستی، مقایسه اهداف و منحنی بودجه
- **قیمت‌ها، باندل‌ها و قوانین مجری**: قیمت لیست و مذاکره‌شده برای هر سازه، سناریوی ±٪ قیمت، قوانین هر مجری (فقط باندل، حداقل مدت، تخفیف) و تعریف باندل‌ها که در پیشنهاد یکجا انتخاب می‌شوند
- **لیدربورد**: همه سازه‌ها با مرتب‌سازی روی هر ستون (امتیاز، ایمپرشن، مواجهه، دید مستقیم، قیمت، CPM، منطقه…)، فیلتر منطقه/نوع/مجری و انتخاب گروهی برای قفل یا حذف از کمپین
- **مناطق شهرداری**: لایه 22 منطقه تهران (مرز از OSM، در نبود آن تقریبی)، خلاصه هر منطقه و محدود کردن کمپین به مناطق انتخابی
- **بهترین سازه‌های هر منطقه**: در تب «سازه‌ها» محدوده را «کل تهران»، «مناطق شهرداری» (یک یا چند منطقه، از پنل یا با کلیک روی نقشه؛ Shift برای افزودن) یا «محدوده نقشه» بگذارید و بر اساس امتیاز، ایمپرشن، ارزش خرید یا CPM مرتب کنید. زوم لازم نیست. جایگاه‌یابی بیلبورد جدید هم داخل منطقه انتخابی کار می‌کند.
- **نقشه حرارتی هفته** (7 روز × 24 ساعت) برای خرید ساعتی تابلوهای دیجیتال
- **امتیاز 0 تا 100** و **مقایسه** چند نقطه کنار هم، با برنده هر شاخص
- ساعات طلایی برای تابلوهای دیجیتال، تفکیک روز کاری / پنجشنبه / جمعه
- لایه **پل‌های عابر و سازه‌های تبلیغاتی** ثبت‌شده در OpenStreetMap برای پیدا کردن سازه‌های بالقوه
- خروجی **CSV (اکسل)**، **گزارش PDF** (چاپ) و **لینک اشتراک** که همه نقاط را برای همکار باز می‌کند

همه‌چیز سمت مرورگر اجرا می‌شود؛ سرور و دیتابیس ندارد و روی GitHub Pages رایگان بالا می‌آید.

## راه‌اندازی روی GitHub Pages

راهنمای کامل و قدم‌به‌قدم (ساخت ریپو، توکن، زمان‌بندی هفتگی با cron-job.org) در [SETUP.md](SETUP.md) است. خلاصه:

1. یک مخزن جدید بسازید و محتوای این پوشه را در شاخه `main` آن push کنید.
2. در مخزن: **Settings ← Pages ← Build and deployment ← Source = GitHub Actions**.
3. workflow موجود در `.github/workflows/pages.yml` خودکار اجرا می‌شود و پیش از انتشار، شبکه معابر و مرز مناطق را از OpenStreetMap در `data/roads.json` و `data/districts.json` می‌سازد. آدرس سایت در تب Actions نمایش داده می‌شود (معمولاً `https://<user>.github.io/<repo>/`).

> راه ساده‌تر: Source را روی **Deploy from a branch** و شاخه `main` / پوشه root بگذارید. فایل `.nojekyll` از قبل هست.

اجرای محلی: `python3 -m http.server` در همین پوشه و باز کردن `http://localhost:8000`. (باز کردن مستقیم فایل `index.html` کار نمی‌کند چون از ES Module استفاده شده.)

### جابه‌جایی خودکار بین منابع (Failover)
در تنظیمات، منابع به ترتیب اولویت چیده می‌شوند (پیش‌فرض: نشان ← Map.ir) و برای هر کدام سقف ماهانه درخواست قابل تعریف است. هر درخواست به اولین منبع آماده می‌رود و در این حالت‌ها خودکار سراغ منبع بعدی می‌رود:
- رسیدن به سقف ماهانه تعریف‌شده (شمارنده در همان مرورگر)
- خطای سهمیه (402 / 429 / 470) ← توقف تا پایان روز
- کلید نامعتبر یا سرویس غیرفعال (401 / 403) ← توقف 24 ساعته
- در دسترس نبودن یا CORS ← توقف 10 دقیقه‌ای

اگر هیچ منبعی آماده نباشد، مدل ترافیک تهران جایگزین می‌شود و ابزار متوقف نمی‌شود. وضعیت لحظه‌ای در نوار بالا (کنار جستجو) دیده می‌شود. Map.ir الگوی ترافیک ساعتی ندارد؛ سرعت مسیر آن با وزن نصف در کالیبره کردن مدل استفاده می‌شود، چون ترافیک‌محور بودن آن تأیید نشده است.

> **بلد:** در حال حاضر API عمومی برای توسعه‌دهندگان ارائه نمی‌کند (فقط نقشه قابل جاسازی). ساختار `js/providers.js` طوری است که با دریافت دسترسی سازمانی، اضافه کردن آن فقط یک ورودی در `PROVIDERS` و یک پیاده‌سازی در `js/net.js` است.

> **شمارنده سقف ماهانه** در مرورگر هر کاربر جداگانه نگه داشته می‌شود؛ مصرف واقعی کل تیم را از پنل نشان / Map.ir ببینید. خطای سهمیه سرور در هر حال جابه‌جایی را فعال می‌کند.

بدون کلید نشان هم ابزار کامل کار می‌کند (با مدل ترافیک تهران). برای دقت بیشتر:

1. در [platform.neshan.org](https://platform.neshan.org) یک کلید API بسازید و سرویس‌های «تحلیل ترافیک»، «مسیریابی» و «جستجو» را برایش فعال کنید.
2. در اپ: آیکون تنظیمات ← کلید را وارد کنید ← «تست اتصال».
3. کلید فقط در مرورگر همان کاربر ذخیره می‌شود و داخل لینک اشتراکی نمی‌رود.
4. برای Map.ir هم از [corp.map.ir](https://corp.map.ir) کلید بگیرید و در کارت دوم وارد کنید.

### اگر تست اتصال خطای شبکه/CORS داد
فایل `proxy/cloudflare-worker.js` یک پروکسی کوچک برای Cloudflare Workers (پلن رایگان) است. بعد از deploy، آدرس آن را در «آدرس پروکسی» بگذارید. اگر کلید را به‌صورت secret روی Worker ذخیره کنید (`NESHAN_KEY`)، کلید هیچ‌وقت به مرورگر همکاران نمی‌رسد و در فیلد کلید اپ کافی است یک متن دلخواه مثل `proxy` بنویسید. با `ALLOWED_ORIGIN` دسترسی را به دامنه GitHub Pages خودتان محدود کنید.

## داده بازار: سازه‌های واقعی و قیمت‌ها

`data/market.json` فهرست واقعی سازه‌های تبلیغاتی تهران با قیمت اعلام‌شده است و هر 7 روز (جمعه 03:07 تهران) با `.github/workflows/data.yml` دوباره ساخته می‌شود.

- **منبع:** مجموعه‌داده باز [Rasamap](https://github.com/alireza-zareian/Rasamap-Repository) (مجوز MIT). این مجموعه آگهی‌های عمومی billboardiha.com، irbillboard.com و aradholding.com را جمع می‌کند. اسکرپر آن (که از ترفندهای دور زدن ضدربات استفاده می‌کند) اینجا اجرا نمی‌شود. فقط خروجی منتشرشده‌اش خوانده می‌شود.
- **بررسی مکان:** آگهی‌هایی که مختصاتشان از بزرگراه نام‌برده در آدرس بیش از 1.2 کیلومتر فاصله دارد، به تقاطع یا نشانی ذکرشده منتقل می‌شوند (`loc: moved`). اگر چنین نقطه‌ای پیدا نشود، روی همان بزرگراه قرار می‌گیرند (`loc: onroad`). آگهی‌هایی که مختصات مشترکِ پیش‌فرضِ شهری دارند یا بیرون از تهران‌اند کنار گذاشته می‌شوند. روی نقشه، سازه با مکان تقریبی حاشیه خط‌چین دارد. اگر نشانگر را بکشید، مکان اصلاح‌شده نگه داشته می‌شود و به‌روزرسانی هفتگی آن را عوض نمی‌کند.
- **قیمت:** قیمت ماهانه به تومان است. قیمت‌هایی که خود Rasamap با فرمول پر کرده (نه از صفحه آگهی) برچسب «برآورد» دارند و در محاسبه قیمت منصفانه حساب نمی‌شوند. اگر قیمت قدیمی یا اشتباه است، در تب «قیمت‌ها» دستی وارد کنید. قیمت دستی جداگانه نگه داشته می‌شود و به‌روزرسانی هفتگی آن را بازنویسی نمی‌کند. قیمت مذاکره‌شده هم فیلد جدایی دارد. ستون «عمر قیمت» نشان می‌دهد آخرین برداشت قیمت چند روز پیش بوده است. بالای 60 روز «قدیمی» می‌شود.
- **تازگی:** قیمت‌ها فقط وقتی تازه می‌شوند که Rasamap داده‌اش را به‌روز کند. برای قیمت قطعی، فید CSV یا گوگل‌شیت خودتان را در تب «قیمت‌ها» وصل کنید.

### ارزش خرید و ضریب ارزشمندی
- **قیمت منصفانه** از یک برازش لگاریتمی روی خود بازار به دست می‌آید: `log(قیمت) = a[نوع سازه] + b·log(ایمپرشن ماهانه)`. یعنی سازه‌ای با این مخاطب، در این بازار معمولاً چند می‌ارزد.
- **ارزش خرید** = قیمت منصفانه ÷ قیمت. عدد 1 یعنی قیمت معمول، 1.4 و بیشتر «خرید عالی» و زیر 0.7 «گران». برای سازه‌ای که مکانش تقریبی است، عدد با «?» نشان داده می‌شود.
- **ضریب ارزشمندی** (از ×0.5 تا ×2، در لیدربورد و تب قیمت‌ها) برای چیزهایی است که مدل نمی‌بیند: مخاطب منطقه، تناسب با برند، کیفیت واقعی دید. این ضریب هم در قیمت منصفانه ضرب می‌شود و هم در هدف بهینه‌سازی کمپین.

## روش محاسبه (خلاصه)

1. **تردد** = تعداد خط در هر جهت × ظرفیت روزانه هر خط (بزرگراه 21,000 · بزرگراه شهری 17,000 · شریانی اصلی 11,000 · شریانی فرعی 7,500 خودرو). توزیع ساعتی با پروفایل ترافیک تهران و رعایت سقف ظرفیت ساعتی.
2. **سرعت ساعتی** = سرعت آزاد × ضریب ترافیک آن ساعت (از نشان یا پروفایل پیش‌فرض)، کالیبره‌شده با سرعت معمول نشان.
3. **زمان مواجهه** = فاصله دید تابلو ÷ سرعت (مثلاً 230 متر در 80 km/h ≈ 10 ثانیه).
4. **ایمپرشن** = تردد × سرنشین (1.5) × احتمال توجه سازه × (1 − e<sup>−t/6</sup>) × سهم نمایش (برای تابلو دیجیتال).
5. **ماهانه** = مجموع هفته با ضریب روزها (پنجشنبه 0.86، جمعه 0.62) × 30/7.
6. **امتیاز** = 70٪ حجم ایمپرشن (مقیاس لگاریتمی) + 30٪ زمان مواجهه.

همه ضرایب در `js/config.js` با توضیح هستند و قابل تنظیم‌اند. اگر آمار شمارش واقعی یک نقطه را دارید (از مالک سازه یا شرکت کنترل ترافیک تهران)، در «مشخصات معبر و فرض‌های محاسبه» وارد کنید تا جایگزین مدل شود.

### قیمت‌ها و به‌روزرسانی هفتگی
مجری‌های تبلیغات محیطی تهران قیمت را بیشتر به‌صورت رِیت‌کارت/پیش‌فاکتور یا در صفحات وبلاگ‌شان می‌دهند و API عمومی ندارند؛ بسیاری از سایت‌ها خواندن خودکار را هم مسدود کرده‌اند. راه پیشنهادی:
1. یک گوگل‌شیت مشترک قیمت (ستون‌ها: کد یا نام سازه، مختصات، مجری، قیمت لیست، قیمت مذاکره‌شده) که تیم از روی رِیت‌کارت‌ها به‌روز می‌کند → File ← Share ← Publish to web ← CSV.
2. آدرس CSV را در `data/price-sources.json` بگذارید و `enabled: true` کنید. workflow فایل `.github/workflows/data.yml` هر 7 روز `data/prices.json` و تاریخچه `data/price-history.csv` را می‌سازد و commit می‌کند؛ اپ هنگام باز شدن آن را می‌خواند.
3. هر منبع دیگر (JSON یا CSV) را هم می‌شود اضافه کرد؛ خواندن سایت مجری‌ها فقط وقتی شرایط استفاده آن سایت اجازه دهد.
تغییر دستی قیمت در اپ با برچسب «دستی» ذخیره می‌شود.

### سازه‌های موجود تهران
حدود 3,000 سازه تبلیغاتی تهران زیر نظر سازمان زیباسازی است و فهرست عمومی با مختصات منتشر نشده. ابزار سه راه دارد: (1) پل‌های عابر و تابلوهای ثبت‌شده در OpenStreetMap خودکار، (2) ورود فایل اکسل/CSV مجری‌ها یا سازمان (ستون‌های نام، عرض، طول، آدرس، نوع، مالک، قیمت — ردیف بدون مختصات با جستجوی نشان / Map.ir مکان‌یابی و «تقریبی» علامت می‌خورد)، (3) ثبت دستی روی نقشه. نشانگرهای واردشده قابل جابه‌جایی‌اند. «کاتالوگ نمونه» 14 سازه از کاتالوگ عمومی معرفان را اضافه می‌کند.

### محدودیت‌ها
- حجم تردد مدل‌سازی شده است، نه شمارش واقعی. برای مقایسه نسبی نقاط قابل اتکاست؛ عدد مطلق را پیش از قرارداد با آمار مالک سازه تطبیق دهید.
- مانع دید (درخت، ساختمان) دیده نمی‌شود و شلوغی بصری فقط از روی تعداد تابلوهای نزدیک تخمین زده می‌شود.
- در برآورد کمپین، همپوشانی مخاطب بین نقاط کسر نمی‌شود (جمع ایمپرشن ≠ ریچ یکتا).
- فرمت پاسخ API تحلیل ترافیک نشان مستند عمومی ندارد؛ پارسر انعطاف‌پذیر نوشته شده و اگر پاسخ قابل استفاده نباشد، اپ خودکار به مدل برمی‌گردد.

## نسخه دمو (بدون اینترنت و کلید)
`npm i && npm run build:demo` یک فایل تکی `dist/demo.html` می‌سازد که با نقشه ساده‌شده تهران و داده شبیه‌سازی‌شده نشان / Map.ir کار می‌کند (برای نمایش به تیم). در دمو سهمیه نشان عمداً نزدیک سقف است تا جابه‌جایی به Map.ir دیده شود.
